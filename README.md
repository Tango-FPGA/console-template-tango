# console-template-tango -- the Tango Template core

**Version 2026-10-28** (date code `20261028`)

console-template-tango is the **Template core** of the Tango FPGA system for the **Sipeed Tang Console 138K**: the
minimal Tango core, and the starting point for writing a new one, as MiSTer developers start from
[Template_MiSTer](https://github.com/MiSTer-devel/Template_MiSTer). Fork it, replace the core and its menu string, and
keep the build, the simulation benches and the framework around them.

Like every Tango core it is built on the framework [sys-tango](https://github.com/Tango-FPGA/sys-tango), which this
repository includes as a git submodule at `sys/`. The BL616 firmware that loads cores and draws their menus is
[firmware-tango](https://github.com/Tango-FPGA/firmware-tango); the launcher is
[menu-tango](https://github.com/Tango-FPGA/menu-tango); [arcade-template-tango](https://github.com/Tango-FPGA/arcade-template-tango)
is the template for arcade cores.

## What the Template core does

`rtl/tango_core_template.v` is a `tango_core` (the framework's core interface, `sys/tango_core_ports.vh`) that does
what Template_MiSTer's core does, plus a few test aids for the framework:

- **The picture:** Template_MiSTer's TV static -- a 63-bit LFSR gives the noise and a cosine wave rolls down the
  screen (`rtl/template_cos.vh`, generated by `tools/gen_cos.py`) -- at 320 x 240 core pixels, scaled to 720p.
- **The menu string (CONF_STR):** Template_MiSTer's, with its options wired as there: TV Mode NTSC / PAL (the roll
  speed), Test Page 1 / 2 with their options and a `BIN` file load (greyed until Option 1-1 is On, through
  `status_menumask`), Reset and Reset and close OSD. Changed from Template_MiSTer's:
  - the framework's **Video** entries in place of its Aspect ratio (`` `TANGO_VIDEO_CONF ``: Aspect ratio, Scale,
    Scanlines; sys-tango README, "The Video page");
  - its Noise entry is left out (the noise stays white);
  - **Pattern** and **Source size**: the test pattern and the native frame size of the scaler build (below);
  - **Audio test**: Off / 1 kHz square / 440 Hz square / Sweep / Noise / 440 Hz left, a signal for the framework's
    audio filter (`tools/template_audio.py` is its model); **Stereo Mix** None / 25% / 50% / 100% (the entry of
    MiSTer's Mega Drive core), which the framework's audio processing applies;
  - `J,A,B`: names the pad's A and B buttons for the firmware's Define buttons;
  - `v,1`: the config version, so the saved options are `config/Template_v1.CFG`.
- **Test aids:** a 24 x 24 white square that joystick 0's d-pad moves; after a `BIN` file load, the file's first
  32 bytes drawn as grey cells at the bottom of the screen (`ioctl_wait` is held 3 clocks after every byte to
  exercise the wait path).
- **The scaler build** (`TANGO_VIDEO_ASCAL`): instead of the static, a test pattern at the chosen source size, through
  the framework's scaler, with the square and the download strip on it:

  | Pattern | What it tests |
  |---|---|
  | 0 Gradient | R = x, G = y, B = 0x80: the colour path, and where the picture lands |
  | 1 Pixel grid | 1-px columns, rows and a checkerboard: at an integer scale every stripe is the same width |

  | Source size | Active | Total | Pixel clock | Frame rate |
  |---|---|---|---|---|
  | 320x240 (default) | 320 x 240 | 400 x 262 | 6.1875 MHz | 59.04 Hz |
  | 256x240 NES | 256 x 240 | 341 x 262 | 5.3036 MHz | 59.36 Hz |
  | 256x224 SNES | 256 x 224 | 341 x 262 | 5.3036 MHz | 59.36 Hz |
  | 384x224 CPS | 384 x 224 | 525 x 262 | 8.25 MHz | 59.98 Hz |
  | 160x144 GB | 160 x 144 | 448 x 154 | 4.125 MHz | 59.79 Hz |

  The OSD's Pattern entry selects a pattern, and joystick 0's A / B step to the next / previous one. To add a
  pattern: a `case` of `pattern()` in the RTL (a function of the native x, y, the size w x h and the frame number),
  `NPAT` + 1, the same function in `tools/template_patterns.py`, and its name in the CONF_STR's Pattern entry.
- **System entries** of the menu (Reboot, Save settings, Define buttons, Video processing, Audio filter) come from
  the firmware, not from the core.

The header of `rtl/tango_core_template.v` describes every behaviour; `NOTICE` lists which of its lines come from
Template_MiSTer.

## Trying it on the board

You need a Tang Console 138K with [firmware-tango](https://github.com/Tango-FPGA/firmware-tango) in its BL616 and
[menu-tango](https://github.com/Tango-FPGA/menu-tango)'s launcher on a FAT32 SD card (firmware-tango's README, "The SD
card"). Copy the release's **`Template_20261028.bin`** to the card as `/_Console/Template_20261028.bin`; the
launcher lists it as "Template". It is the card build (`build/build_template_vproc.sh`: the scaler with its frame
buffers in the DDR3, the framework's video and audio processing); its menu string ends `V,v261018`, the build date
it was built with.

| On the card | What |
|---|---|
| `/_Console/Template_<YYYYMMDD>.bin` | the core |
| `/games/Template/` | files for Load *.BIN (any file: its first 32 bytes are shown) |
| `/config/Template_v1.CFG` | the saved options (System, Save settings) |
| `/filters`, `/filters_audio`, `/gamma`, `/shadow_masks`, `/presets` | MiSTer's filter files, for System, Video processing and Audio filter |

## Building from source

You need, on Linux (x86-64):

- **Gowin EDA** (the IDE with `gw_sh`), V1.9.11.03, with a licence for the GW5AST-138 and its DDR3 Memory Interface
  IP. The framework's `build_core.sh` runs it headless from `$GOWIN_HOME/IDE` (default `~/gowin`) and takes Gowin's
  `PLL_INIT` and the DDR3 IP from that installation (sys-tango README, "Building").
- **Python 3** (the build tools).
- **systemd** user scopes for `tango_capped.sh`, which runs the build in a memory-capped cgroup. A 138K build needs a
  few GB of memory; run one build or simulation at a time.

Get the sources with the framework:

    git clone https://github.com/Tango-FPGA/console-template-tango.git
    cd console-template-tango
    git submodule update --init          # sys/ = sys-tango, at the commit this release was built with

Build:

    build/build_template_vproc.sh        # the card build: scaler + DDR3 + video and audio processing
    build/build_template_ascal.sh        # the scaler build with its frame buffers in the SDRAM
    build/build_template.sh              # the bare core (no scaler: the static at 720p)

Each runs the framework's `sys/board/console138k/build_core.sh` (the Gowin project in `build/out/<name>/`), then the
STA gate (`sys/build_tools/sta_gate.py`: no setup or hold violation, every clock at or above its constraint, a worst
setup slack of at least +0.10 ns, logic and block RAM at most 98%; never use a build whose gate failed), and archives
the result in `$TANGO_ARCHIVE` (default `bitstreams/` in the checkout) as `<name>_<YYYYMMDD-HHMM>_g<commit>...{fs,bin,txt}`
(`..._STA-FAIL` when the gate failed; the `.txt` holds the gate's report and the resource use). The `.bin` is what
goes on the card.

`TANGO_BUILD_DATE=<YYMMDD>` sets the build date in the menu string (the default is today); the release's `.bin` was
built with `TANGO_BUILD_DATE=261018`. `build_template_vproc.sh` also takes the framework's build-time presets, for a
board without the firmware (JTAG tests): `TANGO_PRESET_STATUS=<32 hex digits>` (the option word at power-up) and
`TANGO_VPROC_PRESET="<settings>"` (a compiled-in filter / gamma / mask / audio filter load, from MiSTer's filter
files in `TANGO_FILTERS_ROOT`); its argument is a tag added to the archive name (sys-tango README, "Build options").

## Simulation

You need **Verilator 5** (5.020 tested), a C++ compiler, **Python 3** with **Pillow**, **numpy** and **freetype-py**
(the OSD model renders with FreeType), and `tango_capped.sh`'s systemd user scopes (`sys/build_tools/tango_capped.sh`;
memory cap `TANGO_MEM_CAP`, default 4G). Each bench builds into `sim/obj*/` and prints a PASS / FAIL line:

| Bench | What it checks |
|---|---|
| `sim/run_tb_template_ascal.sh` | **the Template's gate**: the framework (`tango_sys`, `sim/tb_template_ascal.files`) around the core in its scaler build (`TANGO_VIDEO_ASCAL`, with the framework's simulation model of the scaler), on asynchronous clocks; a model of the BL616 plays a session over the SPI link as the firmware does (status, menu string, the OSD page, options in the vertical blank, the menu mask, a file download, pad presses, a reset); the menu string read back must equal the RTL's, every captured frame must show the pattern and source size the session selected (`tools/template_ascal_golden.py`) |
| `sim/run_tb_template.sh` | the same session on the bare core: frames 6, 9, 13, 21, 26, 30 and 32 against `tools/template_golden.py` (the core's model + the OSD model), pixel for pixel, and the menu string read back; it also checks `sys/tango_ov_geom.vh` against the OSD model |
| `sim/run_tb_ascal_sys.sh` | the real scaler (`sys/ascal_ghdl/`, the GHDL netlist) and the SDRAM controller on a model of the board's W9825G6KH SDRAM; `TB_ARGS=+status=<hex>` sets the option word (e.g. `+status=30000000000000000000020000000000`: Wider HV-Integer + Pixel grid); `sim/measure_scale.py` measures where the picture lands |
| `sim/run_vproc_gates.sh [case ...]` | the framework's video and audio processing (`TANGO_VIDEO_PROC`, the scaler at 256 phases, DDR3) with link transfers made from MiSTer's filter files by `sys/build_tools/vproc_preset.py`: each case's last frame against `tools/vproc_golden.py`'s models pixel for pixel, the audio bit for bit against `sys/build_tools/iir_model.py`. Case `nn` needs no files; the others need `FILTERS=<folder>` laid out as a MiSTer SD card's (`Filters/`, `Gamma/`, `Shadow_Masks/`, `Presets/`, `Filters_Audio/`) |
| `sim/run_idle_gates.sh` | "black until the core's first frame" (sys-tango README, "Video") on the same bench: needs `TANGO_FW=<a menu-tango checkout>` for the recorded OSD stream it plays |
| `sim/run_tb_tango_sdram_ab.sh` | the framework's SDRAM controller (ports A / B at a console core's cadence, port C for the scaler, refresh) against the SDRAM model, in two modes at read round trips of 4, 8, 12 and 14 ns: 8, 12 and 14 ns must pass; with the default read capture (`RD_CAP=1`) 4 ns fails by design (the script's header), so the default run ends with exit status 1 |

`tools/vproc_board.py` and `tools/vproc_audio.py` compare an HDMI capture of the board with the same models.

## Making a new core from it

1. **Copy this repository** to `<core>-tango` and start a fresh history; keep `sys/` as the sys-tango submodule
   (`git submodule add https://github.com/Tango-FPGA/sys-tango.git sys`, or this repository's `.gitmodules`). Move the
   framework with `git -C sys pull` and a commit of the new pointer.
2. **The core:** replace `rtl/tango_core_template.v` with your `module tango_core` (its ports:
   `sys/tango_core_ports.vh`). Take `joystick_0/1`, `status` and `ioctl_*` from the ports, drive `status_menumask`
   and `ioctl_wait`, and give your menu string to `tango_conf_rom #(.CONF_STR(CONF_STR))`. Draw your picture on
   `VID_CX` / `VID_CY` -> `VID_RGB` (two clocks later), or drive the scaler's native video (`TANGO_VIDEO_ASCAL`).
   A MiSTer core's `emu` maps onto the same signals (sys-tango README, "Using it in a core").
3. **The menu string:** MiSTer's CONF_STR format; entry 0 is your core's name, which names `games/<CORE>/` and
   `config/<CORE>.CFG` on the card.
4. **The build:** copy `build/build_template_vproc.sh` (or `build_template.sh` for a core without the scaler), set
   `NAME` and your files; add a core `.sdc` if your core has a clock of its own (sys-tango README, "Timing
   constraints"); `TANGO_SDRAM=1` / `TANGO_SD=1` for the SDRAM or a block device.
5. **The simulation:** copy `sim/run_tb_template_ascal.sh` and `sim/tb_template_ascal.files`, replace the models in
   `tools/` with models of your picture, and adapt the session (`sim/tb_template.inc`).
6. **On the board:** the STA gate PASS, the `.bin` in `/_Console/`, launch it from the launcher, and check the
   picture, the OSD (Start+Select), an option, a file load, and System, Reboot.
7. **Licences:** write your own `NOTICE`. A core that replaces the Template's menu string and picture carries none
   of the Template_MiSTer text listed in this repository's `NOTICE`; the framework (`sys/`) keeps its own licences.
   The rest of this repository's own files (build scripts, simulation benches, most of `tools/`) are GPL-2.0-or-later
   too; only the OSD model copies in `tools/osd-model/` are MIT. A core that keeps any GPL-2.0-or-later file is
   GPL-2.0-or-later for that part, so license your core accordingly or replace those files with your own.

## Layout

| Path | What |
|---|---|
| `rtl/tango_core_template.v` | the Template core (module `tango_core`) |
| `rtl/template_cos.vh` | its cosine table (generated by `tools/gen_cos.py`) |
| `build/` | the Gowin builds (above) |
| `sim/` | the benches (above): `tb_template.{v,cpp,inc}` the async-clock bench and its session, `tb_ascal_sys.v` and `tb_vproc.v` the real-scaler benches, `tb_tango_sdram_ab.v` and `sdram_w9825_model.v` the SDRAM controller bench and its SDRAM model, `*.files` the RTL each compiles |
| `tools/` | the core's bit-exact models and golden generators (`template_model.py`, `template_patterns.py`, `template_golden.py`, `template_ascal_golden.py`, `template_page.py`, `template_audio.py`, `vproc_*.py`, `idle_check.py`, `compare_frames.py`) |
| `tools/osd-model/` | the OSD's bit-exact model (copies of menu-tango's, MIT) and its font |
| `sys/` | the framework, [sys-tango](https://github.com/Tango-FPGA/sys-tango) (git submodule) |
